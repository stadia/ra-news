## 긍정적 발견 사항

- HTTPS 강제 + HSTS 2년(`max-age=63072000; includeSubDomains`)
- 서버 사이드 렌더링(Hotwire/SSR) — Googlebot이 JS 없이 전체 콘텐츠 색인 가능
- 서버 응답 속도: `X-Runtime: 93ms`
- 기사 페이지에 canonical 태그 + 메타 디스크립션 존재
- 한국어 번역 품질 우수 (자연스러운 기술 한국어)
- 이중 언어 제목 구조 (`<h2>` 한국어 + `<h3>` 영어 원문) — 독창적 GEO 자산
- 각 기사의 "핵심 요약" 3개 불릿 — AI 인용 가능성 높은 구조
- GA4 + Microsoft Clarity 정상 구현
- RSS 피드 실제로 존재 (`/rss`, 200 OK, 100개 항목)
- `fediverse:creator` 메타태그 존재

## Critical 이슈

### C-1. 사이트맵 완전 부재 — 2,487개 기사 Google 발견 불가

`/sitemap.xml`, `/sitemap_index.xml` 모두 **404**. `robots.txt`에도 `Sitemap:` 지시문 없음.

**근본 원인:** `sitemap_generator` 젬이 Gemfile에 있고 `config/sitemap.rb`도 존재하지만
`bundle exec rake sitemap:refresh`가 한 번도 실행되지 않아 `public/sitemaps/` 비어 있음.

`config/sitemap.rb`의 버그 3개:
1. `find_in_batches`에 `order:` 옵션 전달 불가 → scope에서 먼저 `order()` 호출 필요
2. `lastmod: article.updated_at` → 배경 Job이 건드릴 때마다 갱신 → `published_at` 사용
3. `SitemapGenerator::Sitemap.compress = true`가 `create` 블록 **이후** → 효과 없음

**수정 완료:** `config/sitemap.rb` (Sprint 1 브랜치에 포함)

**실행 필요:**
```bash
bundle exec rake sitemap:refresh
ls -lh public/sitemaps/
```

### C-2. 날짜 데이터 손상 — "20267년", "20268년"

홈페이지 기사 2개가 `20267년`, `20268년` 표시. RSS 피드에서도 동일한 bad data 발견.
`published_at` 컬럼에 잘못된 연도가 저장된 DB 데이터 문제.

**수정 필요 (DB 마이그레이션):**
```sql
UPDATE articles
SET published_at = created_at
WHERE EXTRACT(YEAR FROM published_at) > 2030;
```

### C-3. About/Contact/Privacy 페이지 전무 — E-E-A-T 최대 취약점

`/about`, `/contact`, `/privacy` 모두 **404**.
2025년 9월 Google QRG 기준, 뉴스 집약 사이트는 "콘텐츠 책임자 공개" 필수.

**포함 내용:**
- 사이트 운영자/팀 정보
- 콘텐츠가 AI 보조 번역임을 명시
- 큐레이션 기준
- 연락 방법

### C-4. NewsArticle 스키마 전무 — 2,487개 기사 모두

모든 페이지에 동일한 `WebSite` + `SearchAction` JSON-LD만 존재.
NewsArticle 스키마 부재로 Google 기사 리치 결과/Top Stories 불가.

**수정 완료:** `app/views/articles/show.html.erb`에 NewsArticle JSON-LD 추가 (Sprint 1 브랜치에 포함)

### C-5. robots.txt AI 크롤러 규칙 없음

GPTBot, ClaudeBot, PerplexityBot, CCBot, Google-Extended 등에 대한 정책 전무.

**수정 완료:** `public/robots.txt` 업데이트 (Sprint 1 브랜치에 포함)

## High 이슈

### H-1. 브랜드 불일치 — "RA" vs "Ruby-News"

홈페이지와 `/articles` 페이지 `<title>`, `og:title`, `twitter:title`이 "RA || 루비 AI 뉴스" 사용.

**수정 완료:** 3개 Phlex 뷰 파일 수정 (Sprint 1 브랜치에 포함)
- `app/views/home/index.rb` → "Ruby-News | 루비·Rails 개발자를 위한 AI 뉴스"
- `app/views/articles/index.rb` → "Ruby·Rails 기술 글 모음 2,400+ | Ruby-News 아카이브"
- `app/views/articles/others.rb` → "그 밖의 뉴스 | Ruby-News"

### H-2. twitter:card 태그 완전 부재

`<meta name="twitter:card">` 없음 → X(Twitter) 카드 표시 불가.

**수정 완료:** 레이아웃에 `twitter: { card: "summary_large_image", site: "@rubynewskr" }` 추가

### H-3. 기사 페이지 og:type="website"

모든 기사 페이지가 `og:type: website` 사용 → Facebook, LinkedIn에서 기사 카드 아닌 일반 링크 표시.

**수정 완료:** ArticlesController#show에 `@og_type = "article"`, `@og_article` 설정 추가

### H-4. 홈페이지/articles 메타 디스크립션 없음

**수정 완료:** 레이아웃 `display_meta_tags`에 `description:` 기본값 추가

### H-5. RSS 피드 자동 감지 링크 없음

`/rss`에 RSS 피드 존재하지만 `<head>`에 `<link rel="alternate">` 없음.

**수정 완료:** 레이아웃에 RSS autodiscovery 링크 추가

### H-6. og:url, og:locale 없음

**수정 완료:** 레이아웃에 `og: { url: ..., locale: "ko_KR" }` 추가

### H-7. 혼재된 URL 패턴 — 영상 ID vs 설명적 슬러그

`/articles/po4BcSCogsA` 같은 YouTube ID 형식 URL 존재. 키워드 신호 없음.
이중 percent-encoding 버그도 발견 (`%25` prefix).

**수정 필요 (Sprint 3):** 설명적 슬러그 생성 + 301 리다이렉트
